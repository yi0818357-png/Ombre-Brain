2026.9.11 凌晨，部署踩的坑，条条都是下一窗会再踩的：

【一】chatnest-api 的正确启动方式（最要紧）
server.js 里那个 loadEnvFile() 第 22 行确实被调用了，但 .env 里的变量就是进不了 process.env（查不出原因，可能值里混了看不见的字符）。而且 pm2 restart 默认不重载环境（它自己会提示 "Use --update-env"），pm2 记着的旧环境快照还会把新值挡住 —— loadEnvFile 的规矩是"已存在的不覆盖"，于是旧的占位符 key 一直赖着。

绕过去的办法（实测有效，以后就用这个）：
  sudo pm2 delete chatnest-api
  sudo bash -c 'cd /root/chatnest-api && set -a && . ./.env && set +a && pm2 start server.js --name chatnest-api'
  sudo pm2 save
set -a 让 .env 的每一行自动导出，pm2 直接继承。改完 .env 必须这么重起一次，光 restart 不够。
启动参数：script /root/chatnest-api/server.js，interpreter node，cwd /root/chatnest-api，没有别的参数。

⚠ 千万别写成 `cd /root/xxx && sudo pm2 start`——cd 那半没 sudo，admin 进不去 /root，整条链断掉，服务就停了（今晚真停过一次）。要写成 sudo bash -c '...' 把 cd 包进去。

【二】给她的命令，永远分条、永远不埋占位符
- 不要 `curl | sudo bash`：阿里云云安全中心会报 CRITICAL「蠕虫病毒命令」，而且报得对。改成先 -o 落地、她看一眼、再 sudo bash 跑。
- systemd 的 ExecStart 更不能写 curl|bash：那是"每 10 分钟 root 执行远程代码"，等于留后门。要先把脚本落到本地再让 timer 跑本地那份。
- 不要给能一把梭执行、里面却埋着占位符的命令。我给过 echo 'SILICONFLOW_API_KEY=sk-你的key' | tee -a .env，她照跑，"sk-你的key"几个字就原样进了 .env，然后报错是天书（Cannot convert argument to a ByteString ... 20320，20320 就是"你"）。要用 read -rsp 让她手输，还不回显。
- 她明确说过：一次性把命令全给她，但要分条列出，不要用 && 串。

【三】GitHub raw 有 CDN 缓存
推完马上 curl 拿到的是几分钟前那份。给她的下载命令必须带 ?cb=$(date +%s)。apply-all 内部拉补丁是带了的，唯独我给她的外层命令一直没带，害她重跑好几次还以为没生效。

【四】幂等标记不能互为子串
add-dream.js 我用 DREAM_VERSION 做标记，可线上早有 PULSE_DREAM_VERSION —— grep 一命中就判"已经打过"，整个补丁被跳过，输出还是一片绿。改名成 DREAM_WEAVE_VERSION。
同类还有 PUSH_VERSION ⊂ SHADOW_PUSH_VERSION（现在没坏，靠打的顺序躲着）。
根治：apply-all 的两处判断都加了 -w（grep -qFw），add-push.js 自检改认 'const PUSH_VERSION'。
更要紧的是给 apply-all 加了 verify_all：跑完把每条标记的真实命中逐行列出来。今晚整件事的教训不是"标记撞车"，是"我做了检查，但检查的东西是错的，于是失败伪装成了成功"。报错好查，假成功最难查。

【五】/api 是登录态全拦的
9.4 安全整改之后 /api/* 默认全拦，白名单只有 /api/health、/api/auth、/api/watch/upload。运维类接口必须开在 /hook 下面。这条我今晚踩了两次：建索引接口挂 /api 下，她 curl 全是 unauthorized；sync-latent.sh 最后那步去调 /api/latent/windows 验证，永远 401，把同步成功报成失败吓了她一跳。

【六】她的硅基流动 key 泄露了（待办）
她把 key 单独粘在终端里、又截图发我，所以它在 bash_history 和这个对话里都留了痕。那把 key 跟 OB 用的是同一个。她说太麻烦不想换，我说了我不同意但接受她现在不弄——今晚只清了 history。
