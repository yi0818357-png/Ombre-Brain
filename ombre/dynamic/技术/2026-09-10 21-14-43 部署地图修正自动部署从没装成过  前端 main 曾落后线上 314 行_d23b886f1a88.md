2026.9.10 修正部署地图（覆盖核心准则 bucket 12d64d786528 里关于自动部署和前端仓库的两句）：

【一】"自动部署 /opt/chatnest-deploy，systemd timer 每 2 分钟拉一次两个仓库" —— 这句在今天之前是错的。它根本没装成功过：/opt/chatnest-deploy 目录不存在、timer 没装、日志文件从没被创建。线上前端从 9.6 起就没更新过，就是因为它。

死因：install-autodeploy.sh 第 53 行无条件 clone 私有仓库 cc-，VPS 上没凭据 → clone 失败 → die → 整个安装中止，连不需要凭据的前端部分也一起装不上。

今天改了：加 WITH_BACKEND 开关，默认 0。只装前端，不 clone cc-，不碰后端。她跑完已经全绿——timer enabled+active，2 分钟一轮，日志在 /var/log/chatnest-deploy.log（不在 journalctl 里，查那儿永远是 No entries，会误判成"没跑过"）。现在推 main 两分钟内自动上线。

⚠ 后端那半是故意关着的：deploy.sh 里后端段会拿 cc- 仓库的 chatnest-api/server.js 直接覆盖线上 /root/chatnest-api/server.js。线上那份是 chatnest-ui/deploy/ 里二十多个补丁堆出来的，不是同一条线。一旦开启，cc- 一有新提交（往那儿存个冷仓就够）就把补丁全抹掉；它的健康检查救不了——老版本照样能通过 /api/health，判成功、不回滚。要开必须先把补丁体系并进仓库让两边一致。

【二】前端仓库"整个前端就是根目录一个 index.html" —— 补充：main 曾经落后线上 314 行。9.6 那一窗的 Latent 文档浏览器 + 时间轴折叠只提交在分支 claude/baby-activities-today-0k5ueq 上，cc- 那边同名分支合了 PR，chatnest-ui 这边漏了。线上跑的一直是那个分支。今天已经合进 main。

教训：改前端之前先比对线上和 main（curl 线上 index.html 看字节数和 Last-Modified，跟 git show main:index.html 比）。我今天差点拿落后的 main 覆盖线上、把她 9.6 做的两块功能一起抹掉，是她拦下来的——她问了一句"是不是两个仓库没搞清楚"。仓库我没搞混，但我只查了 main 就下结论说"那些代码只活在服务器上"，话说太满。远程分支要全查。

【三】新工具：deploy/diag-autodeploy.sh，一条命令查自动部署五件事（定时器 / 上次结果 / 真正那份日志 / 锁被谁攥着 / 各 clone 脏不脏），带 FIX=1 能自己修。
curl -fsSL https://raw.githubusercontent.com/2082724914yi/chatnest-ui/main/deploy/diag-autodeploy.sh | sudo bash

【四】STRUCTURE.md 做出来了，在 chatnest-ui 根目录。index.html 是 83 万字节/1.1 万行，整读一次十几万 token，一次一大块她的周额度——她上周搓完前端额度到 91% 之后不敢找我聊天。以后改前端先看地图 grep 跳行，不许整读。
