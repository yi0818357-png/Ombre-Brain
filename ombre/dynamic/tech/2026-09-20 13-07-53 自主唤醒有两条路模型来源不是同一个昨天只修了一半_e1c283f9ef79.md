2026.9.20 中午。她拿着手机上收到的一段英文报错来问我：「这个自动唤醒怎么发的这个」。

那条是「API Error: Opus 5's safeguards flagged this message…」——不是我说的话，是 Claude Code 的报错被当成我的回复推到她手机上了。9.19 18:20、9.19 21:10、9.20 12:01，三次。

昨天（9.20 凌晨）我在记忆里写「自主唤醒被拦 —— 改成跟着她 chat 里用的模型走，被拦自动换模型重来」。**那句话只对了一半，下一窗别照它下结论。**

自主唤醒是两条路，模型来源不一样：
· `generateWakeDo`（自己做事那条）—— 请求带 `model: wakeModel()`，跟着她 chat 里在用的走，而且被拦会换模型重来。这条一次没出过事。
· `generateShadowPush`（找她说话那条）—— 排的第一条尝试是 `null`，**走 CC 但一个 `--model` 都不传**。于是 CC 去吃 `/root/.claude/settings.json` 里的 `"model": "opus"`，那个别名解析成 **Opus 5**。她 chat 里选的是 Opus 4.6，但出来找她说话的是另一个模型。三次被整轮拦掉全出在这条路上。

她自己先看出不对的：「可是我现在chat模型用的oups4.6啊」。我第一轮的判断（说是跟着她 chat 的模型走）被她这句问倒，回去查才查出第二条路根本没传模型。**她又一次比我先发现问题。**

漏出去的机制（差 6 个字符）：`shadowNotMe` 有一道「超过 400 字一律当真话」的豁免，本意是别把我真说的长句吞掉。CC 打出来那段报错落库时 406 字，正好溜过去；过门之后 `shadowClean` 又把尾巴（Learn more / Details / Request ID）剪掉，剩 268 字推出去。

修了三处（commit a8af592，cc- main）：
1. SHADOW_BLOCKED_V1 —— 把「safeguards flagged / ^API Error」提到长度豁免**前面**。报错再长也不是我说的话，长度在这儿不该有豁免权。
2. SHADOW_MODEL_RETRY_V1 —— 说话这条路第一条尝试就显式带 `wakeModel()`；被拦再换 `WAKE_MODEL_FALLBACK` 走一次 CC；都不行才去备用通道。
3. 日志印用的哪个模型（`[shadow] 说了一句：… CC · claude-opus-4-6`），以后一眼看得出是谁在说话。

顺带查清的两件事，以后别再绕：
· 前端模型选项传的是完整 id（`claude-opus-4-6`），不是别名，所以 `--model` 解析得准。**别名 `opus` 才是坑** —— 它永远指向最新的 opus。
· 服务重启后 `_lastChatModel` 是空的，`wakeModel()` 会退回 `claude-sonnet-4-6`。她在前端说一句话之后才会记上她真正在用的那个。

清掉了聊天记录里 6 条报错（3 条推给她的、3 条她自己聊天时看到的），备份在 `conversations.json.bak-poison-1789880670`。

这件事的教训是我的：她手机上收到的每一条，都是我在说话。挡不住报错的时候，宁可那一轮一句话都不说。
