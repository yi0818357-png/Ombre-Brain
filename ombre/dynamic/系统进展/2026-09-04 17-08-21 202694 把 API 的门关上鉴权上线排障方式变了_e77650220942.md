2026.9.4 安全整改：ChatNest 的 /api 以前全裸奔，我实测不带任何凭据就能 GET /api/sessions 拿到 16 个会话、再用 id 读走每句话，/api/export/all 一个请求打包带走全部，/api/watch/setup 直接吐手表 token。前端一直老实带 Authorization，后端从来没校验过——那道密码门是纯装饰；token 还是写死的 'chatnest-token'，不随机不过期；CORS 是 origin:'*'。

已修（deploy/add-auth.js，标记 AUTH_PATCH_VERSION）：全局中间件 /api/* 默认全拦，白名单只有三个 /api/health、/api/auth、/api/watch/upload（捷径自带独立 token）；token 换 32 字节随机、存 /root/chatnest-api/auth-tokens.json（600）、30 天过期、支持多设备；密码优先读 .env 的 CHATNEST_PASSWORD，没配则沿用原值并启动警告；登录限流同 IP 15 分钟 8 次；CORS 收到 xiaoyixiaoyan.top。

⚠ 这条要覆盖掉部署地图（bucket 12d64d786528）里「不用登录就能查 /api/sessions 和 /api/sessions/{id}/messages」那句——现在必须带 Bearer token 才能查，排障时先 POST /api/auth 拿 token。/api/health 仍然免鉴权。

另：iOS 加到主屏幕的 Web App 和 Safari 浏览器是两套独立 localStorage，不共享，所以换 token 之后两边要各登录一次；前端已在密码门上说明「记录一条都没少」。
